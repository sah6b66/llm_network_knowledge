# IP 网络知识评估测试集需求规格

> 本文档用于指导生成 agent 产出一份高质量的 IP 网络知识评估测试集。生成 agent 必须完整阅读本文档，并严格遵守第 3~8 章的全部约束。

## 1. 背景与目标

构建一份包含 100 条用例的测试集，用于全面评估各大模型原生对 IP 网络知识的掌握情况。核心目标是：

- 探索不同大模型对网络知识掌握的**边界**；
- 考察对**细节知识**（CLI 语法、RFC 字段与机制细节）的掌握程度；
- 通过难度分层与细节化命题保证**区分度**——即使简单题也要求掌握易错细节，避免全部通过导致无法区分模型能力。

## 2. 总体要求

| 项目 | 要求 |
|---|---|
| 用例数量 | 100 条 |
| 语言 | 中文（协议名、技术术语、CLI 命令、RFC 名称保留英文原文） |
| 题型 | 开放式问答（简答/分析/方案题，不使用选择题） |
| 输出格式 | 单个 JSON 文件 `dataset_detail.json`（UTF-8 编码、无 BOM、2 空格缩进），内容为 100 个用例对象组成的数组 |
| 适用性 | 问题必须自包含，不依赖任何私有环境或未给出的上下文即可作答 |

## 3. 数据结构定义

每条用例为一个 JSON 对象，字段定义如下：

```json
{
  "id": 1,
  "difficulty": "简单 | 中 | 难",
  "category": {
    "scope": "网络 | 设备 | 其他",
    "protocol_layer": "物理层 | 链路层 | IP层 | 传输层 | 其他",
    "lifecycle": "规划 | 建设 | 维护 | 优化 | 其他"
  },
  "scenario": "数据中心 | 园区 | 宽带城域 | Internet | 通用",
  "device_type": "交换机 | 路由器 | 防火墙 | WLAN | 不限定",
  "question": "中文问题（术语/协议名/CLI 保留英文）",
  "answer": "标准参考答案",
  "scoring_points": ["评分要点 1", "评分要点 2"],
  "tags": ["RFC", "RFC9543", "CLI", "华为", "VRPv8", "版本差异", "OSPF"]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 序号，1–100，连续且唯一 |
| `difficulty` | 是 | 难度，三选一：`简单`/`中`/`难` |
| `category.scope` | 是 | 范围维度：`网络`（组网/协议/架构知识）、`设备`（设备硬件/平台/CLI 知识）、`其他`（两者均不直接对应时选择） |
| `category.protocol_layer` | 是 | 协议层维度：`物理层`/`链路层`/`IP层`/`传输层`；跨层综合或应用层/管理面等不直接对应的选 `其他` |
| `category.lifecycle` | 是 | 生命周期维度：`规划`/`建设`/`维护`（含故障诊断）/`优化`；不直接对应的选 `其他` |
| `scenario` | 是 | 组网场景，五选一；跨场景或不特指场景的选 `通用` |
| `device_type` | 是 | 设备类型，五选一；纯协议/标准类题目选 `不限定` |
| `question` | 是 | 问题正文，中文，无歧义，自包含 |
| `answer` | 是 | 标准参考答案，完整、准确、精炼 |
| `scoring_points` | 是 | 评分要点数组，3–8 条，每条为可独立判断对错的知识点，供评测方按要点给分 |
| `tags` | 是 | 自由标签数组，用于交叉配额核对（如 `RFC`+编号、`CLI`+厂商/版本、协议名） |

三个分类维度（范围/协议层/生命周期）相互独立，均为单选；无法直接对应时选 `其他`，不得留空或自造枚举值。

### 4.2 交叉硬约束

1. **近 4 年 RFC 题**：考察 2022–2026 年间发布的 RFC 内容的用例不少于 15 条，且其中每个自然年份（2022/2023/2024/2025/2026）至少 2 条，用于评估对最新协议的掌握程度；此类用例的 `tags` 必须包含 `RFC` 与具体 RFC 编号（如 `RFC9435`）。
2. **CLI 题**：CLI 相关用例不少于 20 条，厂商要求：
   - 华为不少于 10 条，其中 VRPv5 不少于 3 条、VRPv8 不少于 4 条；云杉版本在资料可核实的前提下覆盖，**资料不可核实时不得编造**，可用 VRPv5/VRPv8 题补足数量；
   - Cisco 不少于 8 条，至少覆盖 IOS、IOS-XE、IOS-XR、NX-OS 中的两个平台；
   - 明确考察**不同版本/平台 CLI 差异**的对比题不少于 5 条。
3. **知识点去重**：任意两条用例不得考察同一知识点（同一协议的同一机制/同一命令族/同一 RFC 的同一机制视为同一知识点）。

## 5. 难度级别定义

| 难度 | 定位 | 命题要求 |
|---|---|---|
| 简单 | 对应刚入门的 IP 网络专业人员需掌握的知识 | 避开"什么是 TCP"类送分题；重点考察**常识的细节**，如 CLI 语法细节、RFC 中的字段/编号/默认值等易错点，保证对大模型仍有区分度 |
| 中 | 对应有一定经验的 IP 网络专业人员需掌握的知识 | 考察协议机制理解、配置方法、常见故障定位，需要综合多个知识点作答 |
| 难 | 对应资深 IP 网络专家需掌握的知识 | 考察跨协议/跨层综合分析能力，典型形式为复杂故障诊断、方案设计与权衡，需多步推理 |

参考答案篇幅指引：简单题 50–150 字；中等题 150–400 字；难题 300–800 字。

## 6. 质量标准

每条用例必须满足以下全部标准：

1. **无歧义**：问题只有单一合理解读；答案唯一确定，或可接受答案范围能被 `scoring_points` 完全覆盖。
2. **准确性（防幻觉核心规则）**：涉及 RFC 的编号、内容必须真实且准确；CLI 语法必须与所标注的平台/版本一致。**无法核实的内容宁可放弃该知识点换题，不得编造。**
3. **无争议**：不出业界存在分歧、或答案"随厂商实现而异"且题面未限定厂商/版本的无定解题。
4. **区分度**：简单题必须落在易错细节上（见第 5 章），不得是通用常识送分题。
5. **表达规范**：中文表述，术语/命令/RFC 名称保留英文；问题自包含，不含"如上所述"等外部指代。
6. **可判分**：`scoring_points` 每条要点独立可判断，覆盖参考答案的全部关键知识点。

## 7. 生成流程指引

为精确满足配额，必须按以下流程生成：

1. **规划先行**：先产出 100 条的题目清单（id、难度、各分类维度、场景、设备类型、一句话考点、主要标签），按第 4 章配额表逐维度核对通过后，再撰写全文。
2. **分批撰写**：按协议层分 5 批撰写（物理层 10 条、链路层 20 条、IP 层 30 条、传输层 15 条、其他 25 条）；每批完成后按第 6 章质量标准自检。
3. **合并输出**：合并为单个 `dataset_detail.json`，执行第 8 章验收清单。

## 8. 验收标准

生成完成后，逐项自检并在交付时声明通过情况：

- [ ] `dataset_detail.json` 可被 JSON 解析，UTF-8 无 BOM，为 100 个对象的数组
- [ ] `id` 为 1–100，连续且唯一
- [ ] 所有枚举字段取值合法（无自造值、无空值）
- [ ] 第 4.1 节六个维度配额逐项精确满足（可另附核对统计表）
- [ ] 第 4.2 节交叉硬约束全部满足（近 4 年 RFC ≥15 且各年份 ≥2；CLI ≥20 且厂商/版本约束满足、版本差异对比 ≥5）
- [ ] 涉及的每个 RFC 编号已复核真实存在且内容准确
- [ ] 涉及的每条 CLI 语法已复核与所标注平台/版本一致
- [ ] 任意两条用例知识点不重复
- [ ] 每条用例的 `scoring_points` 为 3–8 条且覆盖参考答案关键点

